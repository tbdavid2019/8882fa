## 什麼是 PWA

PWA (Progressive Web App) 是一種結合網頁和原生應用優點的應用技術。

### PWA 優勢

| 特性            | 說明                             |
| --------------- | -------------------------------- |
| **📥 可安裝**   | 新增到主螢幕，像原生應用一樣啟動 |
| **⚡ 資源複用** | Service Worker 快取部分資源      |
| **🔄 離線**     | 基礎功能可離線訪問               |
| **🔄 自動更新** | 無需應用商店，自動更新           |
| **💾 小體積**   | 無需下載大型安裝包               |

### WebAPK 支援 (Android)

在支援 WebAPK 且滿足安裝條件的 Android 瀏覽器中，安裝後可以獲得以下體驗；實際安裝形式由瀏覽器和系統決定：

- ✅ 出現在應用抽屜中
- ✅ 可在系統設定中管理
- ✅ 獨立視窗啟動，隱藏常規瀏覽器介面

## 功能特性

### ✅ 已實現功能

#### 1. Web App Manifest (`/manifest.json`)

- 應用名稱、圖示、主題色
- 獨立顯示模式（無瀏覽器UI）
- 快捷方式（快速新增金鑰、掃描二維碼）
- 協議處理器宣告（`web+otpauth`，是否註冊取決於瀏覽器支援）

#### 2. Service Worker (`/sw.js`)

- **靜態資源快取**: 主頁面、Manifest 和應用圖示
- **CDN 資源快取**: jsQR、qrcode-generator
- **智慧快取策略**: 主頁網路優先、Favicon 快取優先、CDN 快取後後臺更新
- **自動更新**: 檢測新版本並自動應用
- **清理舊快取**: 保持儲存空間整潔
- **📴 離線資料修改**: 支援離線新增、修改、刪除和批次匯入金鑰
- **🔄 離線同步**: 支援 Background Sync API，並在頁面載入、網路恢復或 Service Worker 控制器變化時嘗試同步；不支援後臺同步時由開啟的頁面觸發

#### 3. PWA 體驗最佳化

- **📱 安裝入口**: “設定 → 偏好設定 → 安裝到桌面”，瀏覽器觸發安裝事件後啟用按鈕，不自動顯示安裝橫幅
- **📡 離線狀態指示器**: 即時顯示線上/離線狀態，離線時顯示醒目的狀態標識
- **🔄 狀態同步反饋**: 離線操作和同步狀態即時反饋給使用者

#### 4. PWA Meta 標籤

- 提供移動端視口、主題色和 Apple Web App 等元資訊
- 安裝方式、獨立視窗和後臺能力取決於瀏覽器及作業系統，不能僅憑 Meta 標籤保證完整支援

### 📴 離線功能詳解

#### 支援的離線操作

- ✅ **檢視已載入的金鑰列表**
- ✅ **生成 OTP 驗證碼**（本地計算，無需網路）
- ✅ **新增新金鑰**（離線時儲存，網路恢復後自動同步）
- ✅ **修改現有金鑰**（離線時儲存，網路恢復後自動同步）
- ✅ **刪除金鑰**（離線時儲存，網路恢復後自動同步）
- ✅ **批次匯入**（離線時儲存，網路恢復後自動同步）

#### 離線操作流程

1. **離線時的操作**

   ```
   使用者操作 → Service Worker 攔截
     ↓
   儲存到 IndexedDB 離線佇列
     ↓
   返回"操作已儲存"提示（202 狀態碼）
     ↓
   顯示"您處於離線狀態，操作已儲存，網路恢復後將自動同步"
   ```

2. **網路恢復時的同步**
   ```
   網路連線恢復 → Background Sync 或開啟的頁面觸發同步
     ↓
   Service Worker 按時間順序同步所有操作
     ↓
   成功：刪除佇列中的操作，重新整理頁面資料
   網路傳輸失敗：保留佇列，等待後續同步
   HTTP 錯誤等失敗：累計 5 次後標記為失敗
     ↓
   顯示同步結果："已同步 X 個離線操作"
   ```

#### 技術實現

| 元件                    | 說明                                                             |
| ----------------------- | ---------------------------------------------------------------- |
| **IndexedDB**           | 儲存待同步的離線操作                                             |
| **Background Sync API** | 瀏覽器支援時排程後臺同步                                         |
| **頁面同步回退**        | 頁面載入、網路恢復及控制器變化時嘗試同步                         |
| **Service Worker**      | 攔截 API 請求，管理離線佇列                                      |
| **重試機制**            | HTTP 錯誤等累計失敗 5 次後停止自動重試；網路傳輸失敗不消耗該額度 |
| **同步順序**            | 按操作時間戳依次傳送，尚無跨裝置衝突合併                         |

#### 注意事項

⚠️ **離線限制**：

- 離線時無法獲取最新的伺服器資料；頁面可使用已載入或本地快取的列表
- 離線修改需由已啟用並控制頁面的 Service Worker 接收；首次登入、雲端備份及恢復仍需要網路
- 如果多裝置同時離線修改同一金鑰，後同步的操作會覆蓋先同步的
- 建議單裝置使用，或避免在離線時修改相同的金鑰

✅ **資料安全**：

- 離線操作儲存到瀏覽器 IndexedDB，正常關閉頁面後仍可保留；清除站點資料或瀏覽器回收儲存會刪除這些記錄
- 同步需要網路和有效登入會話；請確認同步成功後再清理站點資料
- 不支援 Background Sync 時，需要保持頁面開啟或聯網後重新開啟頁面，才能觸發同步

#### 瀏覽器能力與回退

離線功能依賴 Service Worker 和 IndexedDB。應用會檢測 Background Sync 是否可用；註冊失敗或不支援時，頁面會發送 `SYNC_OPERATIONS` 訊息請求同步。開啟的頁面在網路恢復時也會嘗試同步，並非必須手動重新整理。瀏覽器關閉後的同步時機由瀏覽器決定。

## Service Worker

### 快取策略

當前 `fetch` 處理按以下規則執行：

| 資源                                    | 策略                                                 | 網路異常時的行為                                                                   |
| --------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 主頁面 `/`                              | Network First；成功響應更新快取                      | 返回匹配的頁面快取；無快取時返回 503 離線提示頁                                    |
| Favicon 代理 `/api/favicon/`            | Cache First；成功響應寫入快取                        | 未命中快取且請求失敗時返回空 404                                                   |
| 白名單 CDN 庫（jsQR、qrcode-generator） | Stale While Revalidate；命中快取立即返回並在後臺更新 | 有快取時繼續使用；無快取且網路失敗時載入失敗                                       |
| 其他 `/api/` 請求                       | 網路請求，不快取響應                                 | 受支援的金鑰寫操作可進入離線佇列，成功入隊返回 202；GET 和不受支援的寫操作返回 503 |
| 其他外部資源                            | Network Only；直接透傳，不快取                       | 返回空 404                                                                         |
| 其他同源資源                            | Network Only；不讀取 Service Worker 快取             | 返回 503 文本響應                                                                  |

安裝階段會嘗試預快取主頁、Manifest 和應用圖示；Manifest 和圖示的後續請求目前仍走“其他同源資源”分支，沒有 Service Worker 快取回退。API 的離線佇列只在網路請求丟擲錯誤時啟用，伺服器返回的 HTTP 錯誤會直接傳回頁面。

### 自動更新機制

頁面會註冊 Service Worker，並在開啟期間每小時檢查更新：

- 瀏覽器發現新版後下載並安裝；`skipWaiting()` 和 `clients.claim()` 讓新版儘快接管頁面
- 已開啟頁面中的 HTML 和指令碼不會因此自動重新載入，需要訪問或重新整理頁面才能載入新的介面程式碼
- Service Worker 更新僅記錄控制台日誌，不彈出更新通知

**離線狀態指示器**：即時顯示網路狀態：

- 📡 當網路斷開時，頁面頂部會顯示"離線模式"橫幅
- 🌐 網路恢復時，指示器自動消失，並顯示"正在同步..."提示
- 離線期間的操作會自動儲存到本地佇列
- 網路恢復後自動同步所有離線操作

```javascript
// Service Worker 生命週期

1. 安裝 (Install)
   ↓
   預快取主頁、Manifest 和應用圖示
   ↓
   skipWaiting() - 立即啟用

2. 啟用 (Activate)
   ↓
   清理舊版本快取
   ↓
   clients.claim() - 立即控制頁面

3. 攔截請求 (Fetch)
   ↓
   根據資源型別應用不同快取策略
   ↓
   返回快取或網路響應

4. 更新檢查 (每小時)
   ↓
   檢測新版本 Service Worker
   ↓
   安裝新控制器並記錄日誌，不自動重新整理當前頁面
```

### Service Worker 版本

Service Worker 版本由部署指令碼自動注入。快取名採用 `2fa-cache-${SW_VERSION}`，每次釋出會生成對應的新快取並在啟用階段清理舊版本，無需手工維護固定的 `v1` / `v2` 快取名。

**檢視 Service Worker 狀態**:

1. **Chrome DevTools**:
   - F12 → Application → Service Workers
   - 檢視註冊狀態和快取內容

2. **chrome://serviceworker-internals/**:
   - 檢視所有已註冊的 Service Worker
   - 可以手動解除安裝或更新

## 故障排查

### 問題 1: 安裝按鈕不可用

**原因**:

- 未收到瀏覽器的 `beforeinstallprompt` 事件（應用不會自動顯示安裝橫幅）
- Service Worker 未成功註冊
- 未滿足 PWA 安裝條件
- 瀏覽器不支援 PWA

**解決方案**:

1. **檢查 HTTPS**:

   ```
   確保使用 HTTPS 訪問（Cloudflare Workers 自動提供）
   ```

2. **檢查 Service Worker**:
   - Chrome: `chrome://serviceworker-internals/`
   - 查詢自己的部署域名，或在 DevTools → Application → Service Workers 檢視當前站點
   - 確認已註冊並激活；Service Worker 空閒時停止執行是正常行為

3. **清除快取並重新訪問**:

   ```
   Chrome → 設定 → 隱私和安全 → 清除瀏覽資料
   選擇「快取的圖片和檔案」→ 清除
   ```

4. **檢查瀏覽器安裝入口**:
   - 等待 Service Worker 完成註冊；沒有固定的 30 秒安裝觸發條件
   - 若設定中的按鈕持續置灰，嘗試瀏覽器選單中的安裝或“新增到主螢幕”選項

---

### 問題 2: Service Worker 未註冊

**檢查方法**:

1. 開啟瀏覽器控制台（F12）
2. 檢視是否有錯誤資訊
3. 檢查 Application → Service Workers

**常見錯誤**:

**錯誤 1**: `Failed to register service worker`

```
原因: Service Worker 檔案無法訪問
解決: 確認 /sw.js 可以正常訪問
```

**錯誤 2**: `DOMException: Only secure origins are allowed`

```
原因: 未使用 HTTPS
解決: 使用 HTTPS 訪問（Cloudflare Workers 自動提供）
```

---

### 問題 3: 離線功能不工作

**檢查清單**:

1. ✅ Service Worker 已註冊並激活
2. ✅ 至少訪問過一次線上版本（預快取資源）
3. ✅ 已載入金鑰列表或存在本地金鑰快取；需要的二維碼庫也已線上載入並快取

**可用的離線功能**:

- ✅ 主頁面UI
- ✅ 檢視已儲存的金鑰
- ✅ 生成 OTP（基於本地時間）
- ✅ 二維碼生成（CDN 庫已快取）
- ✅ 新增、編輯、刪除及批次匯入的請求排隊（Service Worker 已控制頁面，成功儲存到 IndexedDB 後返回 202）

**需要網路的功能**:

- ❌ 將排隊的金鑰修改提交到伺服器、獲取最新金鑰列表
- ❌ 雲端備份和恢復（需要 API）
- ❌ 登入認證（需要 API）

---

### 問題 4: 應用未更新到最新版本

**手動觸發更新**:

1. **瀏覽器重新整理**:
   - 按 `Ctrl+Shift+R` (Windows/Linux)
   - 按 `Cmd+Shift+R` (macOS)

2. **解除安裝並重新安裝**:
   - Android: 設定 → 應用 → 2FA → 解除安裝
   - iOS: 長按圖示 → 刪除
   - 桌面: 右鍵圖示 → 解除安裝
   - 重新訪問網站並安裝

3. **清除 Service Worker**:
   ```
   chrome://serviceworker-internals/
   找到自己的部署域名
   點選「Unregister」
   重新整理頁面重新註冊
   ```

---

### 問題 5: CDN 資源載入失敗

**現象**:

- 二維碼掃描功能不可用
- 二維碼生成功能不可用
- 控制台顯示 CDN 資源載入錯誤

**解決方案**:

1. **檢查網路連線**:
   - 確保可以訪問外部 CDN

2. **清除快取**:

   ```
   Chrome → F12 → Application → Cache Storage
   只刪除目標資源快取，然後線上重新載入對應功能
   ```

   不要把清除快取與清除全部站點資料混為一談；後者還會刪除尚未同步的 IndexedDB 操作。

3. **檢查 Service Worker 快取**:
   ```
   Chrome → F12 → Application → Cache Storage
   檢視當前 `2fa-cache-*` 快取
   確認 jsQR.min.js 和 qrcode.min.js 已快取
   ```

## PWA 最佳實踐

### 使用者體驗

1. **定期訪問線上版本**:
   - 確保獲得最新功能和安全更新
   - 更新快取資源

2. **及時同步資料**:
   - 離線資料變更會先進入本地佇列，仍需在網路恢復後完成同步

3. **保持應用更新**:
   - 部署新版後線上重新整理頁面，載入最新介面程式碼；Service Worker 更新不會彈出通知

### 效能驗證

載入耗時受裝置、網路、快取狀態和金鑰數量影響，沒有統一的時延保證。主頁線上時使用 Network First，後續訪問也會請求網路。可使用瀏覽器 DevTools 分別記錄首次訪問、已有快取的線上訪問及離線訪問，比較實際耗時和資源命中情況。

## 技術規格

### Service Worker API 版本

| API                      | 專案實現狀態                                   |
| ------------------------ | ---------------------------------------------- |
| Cache API                | 已實現頁面及指定資源快取                       |
| Fetch API                | 已實現請求分流、離線回退和寫入排隊             |
| IndexedDB                | 已實現持久化離線操作佇列                       |
| Background Sync          | 已實現 `sync-operations`，含頁面觸發回退       |
| Push Notifications       | 僅有接收和點選處理器，未提供完整訂閱與傳送流程 |
| Periodic Background Sync | 未實現                                         |

### 瀏覽器支援

專案通過能力檢測使用 Service Worker、安裝事件和 Background Sync。上表描述程式碼中已實現的功能，並非對所有瀏覽器的相容性承諾。請在目標瀏覽器驗證安裝入口、離線快取和恢復聯網後的同步；HTTPS（或本地開發的可信來源）是 Service Worker 的前提。

## 未來計劃

### 尚未實現的擴充套件

- 週期性後臺同步（當前每小時檢查 Service Worker 更新依賴頁面保持執行）
- 跨裝置離線修改的自動衝突檢測與合併
- 完整的推送通知訂閱與傳送流程

離線操作佇列、金鑰增刪改及批次匯入請求的排隊、Background Sync 和頁面同步回退已經實現，不屬於未來功能。服務端定時備份與瀏覽器週期性後臺同步是不同機制。
